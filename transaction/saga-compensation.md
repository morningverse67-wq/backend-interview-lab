# DP-15. Saga에서 중간 단계가 실패하면 어떻게 되돌리나요?

## 30초 답변

여러 서비스에 걸친 작업은 한 트랜잭션으로 묶을 수 없어서, 앞 단계를 거꾸로 되돌리는 보상 작업이 필요합니다. 직접 재 보니 주문 1만 건(재고 → 결제 → 배송) 중 1,148건이 실패했고, 보상이 없으면 재고 845건과 결제 336건이 그대로 남았습니다. 보상을 한 번만 시도하면 73건이 남았고, 재시도하면 응답만 유실된 보상이 두 번 반영돼 61건이 어긋났습니다. 보상에 멱등 키를 붙이고 재시도하자 0건이 됐습니다.

## 조금 더 깊게

- 보상 호출도 실패할 수 있어서 재시도가 필요합니다. 다만 "처리됐는데 응답만 유실"된 경우 재시도가 같은 보상을 한 번 더 일으킵니다.
- 그래서 보상에는 주문 번호 + 단계 같은 멱등 키를 붙여 한 번만 반영되게 합니다(lab 032와 같은 원리).
- 재시도 횟수를 넘겨도 안 되는 건은 사람이 보는 목록으로 넘깁니다.

## 직접 측정한 근거

| 방법 | 묶인 재고 | 남은 결제 | 재고 해제 중복 | 환불 중복 | 어긋난 건수 합계 |
|---|---:|---:|---:|---:|---:|
| 보상 없음 | 845 | 336 | 0 | 0 | 1,181 |
| 보상 1번만 시도 | 51 | 22 | 0 | 0 | 73 |
| 재시도 (멱등 아님) | 0 | 0 | 48 | 13 | 61 |
| 재시도 + 멱등 키 | 0 | 0 | 0 | 0 | 0 |

- 재현 코드: [backend-lab/040-saga-compensation](https://github.com/morningverse67-wq/backend-lab/tree/main/labs/040-saga-compensation)

<sub>Python 3.13.12, macOS arm64, 시드 40 시뮬레이션. 여러 번 돌려도 숫자가 같았습니다.</sub>

## 꼬리 질문

**Q. 보상은 어떤 순서로 하나요?**  
성공한 단계를 거꾸로 되돌립니다. 실험에서도 배송 등록이 실패하면 결제 환불, 재고 해제 순서로 처리했습니다.

**Q. 보상이 계속 실패하면요?**  
재시도 한도(실험에서는 5번)를 넘긴 건을 수동 처리 목록에 남기고 알림을 보냅니다.

## 흔한 오답

- "보상은 롤백과 같습니다" → 롤백은 DB가 알아서 되돌리지만, 보상은 별도 호출이라 실패하거나 중복될 수 있습니다.

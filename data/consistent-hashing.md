# DP-05. Consistent hashing은 왜 쓰나요?

## 30초 답변

여러 캐시·샤드 노드에 키를 나눌 때 `hash(key) % N`을 쓰면, 노드 수가 바뀌는 순간 대부분의 키가 다른 노드를 가리키게 됩니다. Consistent hashing은 키와 노드를 같은 해시 링에 올려서, 노드가 늘거나 빠질 때 그 노드 주변 구간의 키만 옮기게 합니다. 직접 재 보니 키 10만 개를 노드 10대에서 11대로 늘렸을 때 `hash % N`은 90.89%가 옮겨졌고, 가상 노드 100개짜리 해시 링은 9.27%만 옮겨졌습니다. 다만 가상 노드 없이 쓰면 노드끼리 받는 양 차이가 커서, 가상 노드 수를 같이 정하겠습니다.

## 조금 더 깊게

```python
# 링 만들기: 노드마다 가상 노드 v개를 해시해서 정렬
points = sorted((h(f"{node}#{i}"), node) for node in nodes for i in range(v))

# 키 찾기: 키 해시보다 큰 첫 점의 노드 (끝을 넘으면 처음으로)
i = bisect.bisect(hashes, h(key))
owner = owners[i % len(owners)]
```

- 노드가 하나 늘면 링 위에 새 점들이 생기고, 각 점 바로 앞 구간의 키만 새 노드로 갑니다. 다른 노드끼리는 키를 주고받지 않습니다. 이상적으로 옮겨지는 양은 `1 / (새 노드 수)`입니다.
- 노드마다 점을 하나만 찍으면 구간 길이가 운에 따라 크게 달라집니다. 그래서 한 노드를 링 위 여러 점(가상 노드)으로 나눠서 고르게 만듭니다.
- 쓰는 곳: 여러 대의 캐시 서버에 키를 나누는 클라이언트, 키 범위를 노드에 나누는 분산 저장소(Amazon Dynamo 논문, Cassandra 등).

## 직접 측정한 근거

키 10만 개를 노드 10대에 나눈 뒤, 노드를 11대로 늘리거나 9대로 줄였습니다.

| 방식 | 추가 시 옮겨진 키 | 제거 시 옮겨진 키 | 최대 노드/평균 | 최소 노드 |
|---|---:|---:|---:|---:|
| 이상값 | 9.09% | 10.00% | 1.00 | 10,000 |
| `hash % N` | 90,890 (90.89%) | 90,113 (90.11%) | 1.01 | 9,879 |
| 링, 가상 노드 1 | 268 (0.27%) | 6,243 (6.24%) | 3.72 | 2,004 |
| 링, 가상 노드 10 | 7,522 (7.52%) | 8,956 (8.96%) | 1.51 | 6,492 |
| 링, 가상 노드 100 | 9,266 (9.27%) | 11,432 (11.43%) | 1.14 | 8,111 |
| 링, 가상 노드 1000 | 8,880 (8.88%) | 10,158 (10.16%) | 1.04 | 9,600 |

- 가상 노드 100개 링에서 노드를 추가했을 때 옮겨진 9,266개는 전부 새 노드로 갔습니다. `hash % N`은 90,890개 중 9,090개만 새 노드로 가고, 81,800개는 기존 노드끼리 자리를 바꿨습니다.

## 꼬리 질문

**Q. 가상 노드 1개일 때 옮겨진 키가 0.27%로 가장 적은데, 그게 제일 좋은 것 아닌가요?**  
새 노드가 우연히 링의 짧은 구간에 떨어져서 키를 268개만 받은 것입니다. 노드를 늘린 효과가 거의 없었다는 뜻입니다. 같은 설정에서 가장 바쁜 노드는 평균의 3.72배를 받았습니다. 옮겨지는 양은 적은 것보다 이상값(1/N)에 가까운 것이 좋습니다.

**Q. 가상 노드는 많을수록 좋나요?**  
고르게 되는 대신 링이 커집니다. 실험에서 최대/평균이 100개에서 1.14, 1000개에서 1.04로 좋아졌지만, 이 Python 구현의 조회 시간은 10만 건에 약 25ms에서 36ms로 늘었습니다. 노드 수와 허용할 쏠림을 보고 정하겠습니다.

**Q. 노드가 빠지면 몇 개가 옮겨지나요?**  
빠진 노드가 갖고 있던 키만큼입니다. 가상 노드 100개 실험에서 빠진 노드가 마침 가장 많은 11,432개를 갖고 있어서 11.43%가 옮겨졌습니다.

## 흔한 오답

- "Consistent hashing을 쓰면 키가 고르게 나뉩니다" → 점 하나씩이면 가장 바쁜 노드가 평균의 3.72배였습니다. 고르게 만드는 것은 가상 노드입니다.
- "`hash % N`은 분산이 나빠서 안 씁니다" → 노드 수가 고정이면 오히려 가장 고르게 나뉩니다(최대/평균 1.01). 문제는 노드 수가 바뀔 때 90%가 옮겨지는 것입니다.
